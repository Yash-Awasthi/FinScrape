# Hot query plans

Generated by `python -m scripts.explain --write` against
`postgresql://***@127.0.0.1:5439/worldfin_test` with **20000** synthetic events. Do not hand-edit: the point of
this file is that the plans are reproduced, not asserted. `make explain-check`
fails when a filtered feed read no longer uses an index.

The plan's schema mapping: the plan names `published_at`/`topic`/`ticker`; the
table stores `timestamp`, `event_type`/`sector_impact` and `tickers` (jsonb, GIN).

| Read | Index used | Plan (top node → leaf) | Time (ms) |
|---|---|---|---|
| Feed, one verdict (the common filtered read) (`events_verdict`) | `events_pkey` | Limit → Index Scan(events)[events_pkey] | 0.083 |
| Feed, one ticker (jsonb membership) (`events_ticker`) | `events_pkey` | Limit → Index Scan(events)[events_pkey] | 0.063 |
| Feed, one day (`events_date`) | `idx_events_timestamp` | Limit → Sort → Index Scan(events)[idx_events_timestamp] | 0.022 |
| Dashboard totals (`stats`) | **sequential** | Aggregate → Seq Scan(events) | 5.533 |
| Track record join (`accuracy`) | `events_pkey` | Aggregate → Sort → Nested Loop → Seq Scan(accuracy_outcomes) → Index Scan(events)[events_pkey] | 0.022 |
| Recent correlation signals (`correlations`) | **sequential** | Limit → Sort → Seq Scan(correlations) | 0.026 |
| Storylines cache key (newest 200) (`storylines_head`) | `events_pkey` | Aggregate → Limit → Index Only Scan(events)[events_pkey] | 0.080 |

## What `--check` enforces

Only the filtered reads (feed by verdict, ticker, day) must avoid a sequential
scan of `events`. Aggregates (`count(*)`, `max(created_at)`) and the small
`correlations`/`accuracy_outcomes` joins are allowed to scan: a seq scan is the
correct plan when the read covers the whole table.
